# ADR-0001：服务器同步采用模块化单体与 PostgreSQL

## Status

Accepted

## Context

投记需要从本地优先的个人账本扩展为邀请制多用户产品。系统需要账号隔离、可靠同步、事务写入和可恢复备份，同时由个人维护，预算和运维能力有限。

## Decision

采用 Node.js 模块化单体作为 API 服务，PostgreSQL 作为主数据库。前端继续保留 localStorage 离线账本，通过同源 HTTPS API 与服务器同步。使用账本 revision 实现乐观并发控制，冲突时拒绝写入并要求客户端重新合并。

## Consequences

### Positive

- 单次部署，适合个人维护和当前规模。
- PostgreSQL 事务与约束适合账本数据。
- 模块边界为以后拆分服务保留空间。
- revision 冲突机制避免设备间静默覆盖。
- 保留本地模式，服务器故障不会立即阻止记账。

### Negative

- 需要维护数据库、备份、HTTPS 和安全更新。
- 第一版服务端可以读取用户账本，不是端到端加密。
- 单服务器故障会暂时中断登录与云同步。

### Neutral

- GitHub Gist 同步暂时保留，后续根据使用情况决定是否下线。
- 第二台 AWS 只用于测试和备份，不承担实时流量。
## Alternatives Considered

### 单个 JSON 文件同步服务

实现简单，但无法可靠处理多用户隔离、并发写入、事务和查询，因此拒绝。

### AWS RDS

降低数据库运维工作，但第一阶段持续成本更高。先使用自托管 PostgreSQL，用户规模或可用性要求提高后再评估迁移。

### 微服务

账号、同步和账本模块可以拆分，但当前规模没有独立扩缩容需求，部署和排障成本过高，因此拒绝。

### MongoDB

数据模型灵活，但账本更需要事务、唯一约束和关系查询，PostgreSQL 的 JSONB 已能兼顾兼容性，因此拒绝。
