# 投记与个人站统一账号设计

## 目标

个人站账号成为 `orbitshz.com` 与 `ledger.orbitshz.com` 的唯一身份。投记不再展示独立登录、注册或管理员界面；个人站账号中心负责登录、邀请与成员管理。

## 身份与数据

- Caddy 在投记页面与 API 前调用个人站内部授权接口。
- 授权接口只向本机 Caddy 返回用户 ID、邮箱和角色。
- Caddy 覆盖客户端同名请求头，再把可信身份传给仅监听回环地址的投记 API。
- 投记以 `orbit_user_id` 关联 PostgreSQL 用户，并为首次访问者自动创建空账本。
- 个人站 `owner` 映射为投记 `admin`，`friend` 映射为 `user`。
- 每个身份只能读取自己的账本；管理员 API 只返回元数据与数量。

## 退出与本地数据

- 投记的退出命令调用个人站账号服务注销共享会话，然后立即离开投记页面。
- Caddy 会阻止已退出用户重新打开投记。
- 页面在重新获得焦点时检查会话，已失效则立即锁定并跳转登录。
- 浏览器记录当前绑定的个人站用户 ID。若同一浏览器切换到另一个账号，先清空当前可见账本，再从新账号的服务器账本加载，避免跨账号显示旧数据。
- 同一账号再次进入时仍可使用本地副本，保持离线与快速启动体验。

## 产品界面

- “同步数据”只展示服务器同步状态、比较同步和本地/服务器数量。
- 账号资料、退出、邀请和成员管理统一放在个人站 `/account`。
- 个人站账号中心增加投记服务状态与使用数量，站主可查看用户级数量汇总，但看不到流水或持仓正文。

## 回退

上线前分别备份 PostgreSQL、Orbit SQLite、Caddy 配置和两端静态文件。回退代码不删除新增列；旧数据与账本关联保持可恢复。
