# 投记管理员中心设计

## 目标

为投记增加最小但完整的管理员能力，同时保持账本内容对管理员不可见；在个人主页顶部导航增加明确的“投记”入口。

## 权限边界

- 用户角色只有 `user` 与 `admin`。
- 普通用户只能访问自己的账本。
- 管理员可以查看用户邮箱、角色、状态、注册时间、最近活动时间，以及流水/持仓数量。
- 管理员不能读取任何用户的流水或持仓 payload，也不能调用其他用户的同步接口。
- 管理员可以停用或恢复普通用户，但不能停用自己，也不能在网页中修改角色。
- 管理员可以创建和撤销普通邀请码；管理员邀请码只能由服务器命令行生成。
- 邀请码原文只在创建时返回一次，数据库继续只保存 HMAC 摘要。

## 架构

PostgreSQL 迁移为 `users` 和 `invitation_codes` 增加角色字段。认证服务在公开用户对象和会话中携带角色。新的 admin 模块通过独立授权中间件保护，所有查询只返回元数据和聚合计数。

单文件 Vue 前端在“同步数据”模块中为管理员展示管理中心，提供概览、用户状态管理和邀请码管理。个人主页只增加顶部导航入口，不改变原有项目卡片与账号系统。

## 安全与失败处理

- 所有管理写操作要求有效管理员会话并通过同源检查。
- 用户状态和路径参数使用严格校验。
- 停用用户时删除其全部会话，使状态立即生效。
- 创建邀请使用现有安全随机码与服务端 HMAC。
- 管理接口不返回密码摘要、会话、邀请码摘要、流水 payload 或持仓 payload。
- API 错误使用固定代码，不泄露数据库细节。

## 验证

- 数据库迁移与重复执行测试。
- 普通用户访问管理 API 返回 403。
- 管理员可读取汇总、创建/撤销邀请、停用/恢复普通用户。
- 管理员不能停用自己。
- 管理 API 响应中不存在账本 payload。
- 投记静态测试、服务器测试、个人主页构建与渲染测试全部通过。
